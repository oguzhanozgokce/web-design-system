# Reorderable list study

Reviewed 2026-11-08. These are visual and interaction references, not copied component sources.
The current API is documented in `content/docs/components/data-display/reorderable-list.mdx`.

| Reference | Observed pattern | Application |
| --- | --- | --- |
| [beUI Sortable Stack](https://beui.dev/components/motion/sortable-stack) | A grip, calm outlined rows, icon tiles, descriptive text, position numbers and Undo | Clear reorder affordances and an application-owned Undo example. Original row implementation and examples. |
| [HeroUI ListBox](https://heroui.com/en/docs/react/components/list-box) | Soft shapes, compact content hierarchy and focus treatment | Use Highwren's established corners, 40px controls and focus ring. Selection is a separate concern. |
| [Astryx motion lab](https://astryx.atmeta.com/sandbox/pages/motion-lab/previews/) | Position changes explain list updates; reduced motion removes spatial changes | Short transform-only placement animation, governed by the existing motion provider. |
| [React Aria GridList](https://react-aria.adobe.com/GridList) and [drag and drop](https://react-aria.adobe.com/dnd?component=GridList) | Reordering with keyboard and assistive-technology support, interactive row content, named drop indicators | Use the primitive's drag lifecycle, announcements and focus management. Own only array reordering, styling and layout animation. |

## Decisions

- A dedicated `ReorderableList` complements the existing selectable `ListBox`. Grid semantics allow
  row actions such as switches without nesting interactive controls inside a listbox option.
- `outline` presents separate raised rows; `plain` fits an existing settings surface. Rendered
  content supports icons, thumbnails and controls without a slot for every possible design.
- Commit order only on drop. The source dims and an insertion line identifies the target;
  neighbouring rows animate to their new positions after commitment. This avoids rerunning
  consumer state updates on every pointer move.
- Use stable item keys, preserve object identity and skip no-op changes. Controlled state lets
  applications accept, reject, save or undo the result without a second persistence API.
- No bundled external drag engine or spring loop. React Aria and Motion are existing dependencies.
- Vertical internal reordering is the scope. This is not a tree, multi-column board, transfer
  list or virtualizer. Disabled items cannot be dragged but are not position locks.

## Provenance

No beUI, HeroUI or Astryx component source was copied or adapted. Their public demonstrations
informed visual and interaction choices. The array algorithm, styling, composition and examples
were written in this repository using installed React Aria and Motion APIs; no item credits are
needed for this original implementation. Example photos are the repository's procedural
`public/samples` assets, generated by `scripts/generate-samples.ts`.
