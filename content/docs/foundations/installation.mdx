Components install as source through the shadcn CLI. Start with **React 19, TypeScript and
Tailwind CSS 4**, plus an `@/*` alias pointing to your source root. Next.js is optional.

The public production namespace is `https://ui.highwren.com/r/{name}.json`.
Run the commands below in your consuming app; no repository checkout or credentials are required.

## Set up your app

<Steps>
<Step>

### Point the project at the registry

If your project already has a `components.json`, merge the `@ds` registry entry and keep your
existing aliases and settings. Otherwise, use the configuration below with paths that match your app.
For Vite or another client-only app, set `rsc: false` and use your actual stylesheet path, such as
`src/index.css`. The examples below use the displayed aliases; imports follow your configured paths.

```json title="components.json"
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "style": "new-york",
  "tsx": true,
  "rsc": true,
  "tailwind": { "css": "app/global.css", "baseColor": "neutral", "cssVariables": true },
  "aliases": {
    "components": "@/components",
    "ui": "@/components/ds",
    "lib": "@/lib/ds",
    "hooks": "@/hooks/ds",
    "utils": "@/lib/ds/utils"
  },
  "registries": {
    "@ds": "https://ui.highwren.com/r/{name}.json"
  }
}
```

</Step>
<Step>

### Install the theme

Run this in the project where you want to use the components:

```bash
npx shadcn@4.23.0 add @ds/theme @ds/ds-provider @ds/button
```

This installs the theme, provider and first component, including their dependencies and licence
notices. Add other components later with `npx shadcn@4.23.0 add @ds/sidebar`, for example.

Import the theme after Tailwind in the global stylesheet:

```css title="app/global.css"
@import 'tailwindcss';
@import '../styles/ds/theme.css';
```

The theme installs at the project root. From `src/app/global.css`, use `../../styles/ds/theme.css`;
from `src/index.css`, use `../styles/ds/theme.css`. See [Theming](/docs/foundations/theming) to change your brand.

</Step>
<Step>

### Wrap the app in DSProvider

`DSProvider` connects locale, navigation, labels, icons and motion:

```tsx title="app/providers.tsx"
'use client';

import type { ReactNode } from 'react';
import { DSProvider } from '@/components/ds/ds-provider';

export function Providers({ children }: { children: ReactNode }) {
  return <DSProvider locale="en">{children}</DSProvider>;
}
```

Render your app inside this wrapper and import the global stylesheet at the app's entry point:

```tsx
<Providers>{children}</Providers>
```

In a Vite app, the same `DSProvider` can wrap the app inside `createRoot(...).render(...)`.
Match document `lang` and `dir` to the locale. Connect a router with
`navigate={(href) => router.push(href)}`.

</Step>
<Step>

### Add components

The first command already installed Button. Import it to use it in your app:

With the displayed aliases, UI files install in `components/ds`, helpers in `lib/ds` and hooks in
`hooks/ds`, relative to your source root. Keep the installed `licenses/ds/LICENSE` and
`licenses/ds/NOTICE` when redistributing source.

```tsx
import { Button } from '@/components/ds/button';

export function SaveAction() {
  return <Button>Save</Button>;
}
```

</Step>
</Steps>

## Update installed source

The public registry follows verified `production` commits. Installed files belong to your project;
updates are applied when you choose. Use `shadcn@4.23.0`, the CLI version verified here, to preview
an update before replacing a customised copy:

```bash
npx shadcn@4.23.0 add @ds/button --diff
```

Keep local changes under version control and review any overwrite. This library is pre-1.0;
component APIs may change between releases.

## Develop against a local registry

Clone the repository and follow its [setup guide](https://github.com/oguzhanozgokce/web-design-system#run-the-catalogue).
The catalogue requires Node.js 24 or newer. In the registry checkout, run:

```bash
npm ci
npm run registry:build
npm run dev
```

In your consuming app's `components.json`, replace the `@ds` URL with the origin printed by Next.js,
for example `http://localhost:3000/r/{name}.json`. Rebuild registry JSON after changing installable files.

Maintainers can find publication, verification and recovery steps in the
[hosting guide](https://github.com/oguzhanozgokce/web-design-system/blob/main/docs/registry-hosting.md).
