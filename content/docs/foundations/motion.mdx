## Easings and durations

| Utility         | Curve                                  | Used for                                             |
| --------------- | -------------------------------------- | ---------------------------------------------------- |
| `ease-fluid`    | `cubic-bezier(0.32, 0.72, 0, 1)`       | Sliding indicators, the switch thumb, sheets, toasts |
| `ease-out-quad` | `cubic-bezier(0.25, 0.46, 0.45, 0.94)` | Dialog entrance, disclosure height                   |
| `ease-out`      | Tailwind's default                     | Colour, border, shadow and background changes        |
| `ease`          | The CSS keyword                        | Press scale, popover entrance and exit               |

Durations are 100ms for colour, 150ms for popovers and chevrons, 200ms for exits, 250ms for
presses, dialogs and indicators, 300ms for the switch thumb and 350ms for toasts.

In JavaScript, `motionEasings` and `motionDurations` from `@/lib/ds/motion` carry the same values,
and `fluidTween()` returns a `motion` transition on the fluid curve.

## Keyframes

Overlays animate on React Aria's `data-entering` and `data-exiting` attributes with the keyframes
in `theme.css`:

| Utility                                 | Motion                                                                               |
| --------------------------------------- | ------------------------------------------------------------------------------------ |
| `animate-ds-popover-in` / `-out`        | 150ms in from 95% (90% for popovers and tooltips), 4px toward the trigger; 100ms out |
| `animate-ds-dialog-in` / `-out`         | 250ms in from 105% on `ease-out-quad`; 100ms out to 95%                              |
| `animate-ds-sheet-in-{side}` / `-out-`  | 250ms in and 200ms out on `ease-fluid`; start and end follow `dir`                   |
| `animate-ds-fade-in` / `-out`           | Scrims and reduced-motion fallbacks                                                  |
| `animate-ds-spin`, `-shimmer`, `-pulse` | Spinners, skeleton shimmer, pulsing placeholders                                     |

## Springs

Springs are for gestures that carry velocity: dragging a sheet, swiping a toast, the digits of a
[Rolling number](/docs/components/data-display/rolling-number), the morph of a
[Dynamic island](/docs/components/feedback/dynamic-island).
`spatialSpring('fast')` and `effectSpring()` from `@/lib/ds/motion` return transitions for the
`motion` package, and the generator also writes each spring as a CSS `linear()` easing with its
settle time (`--ds-ease-spatial`, `--ds-duration-spatial`).

`data-motion-profile="productive"` on any ancestor switches to calmer, less bouncy springs, the
right choice for dense admin screens.

## Reduced motion

`DSProvider motion` accepts `system`, `reduced` or `disabled`.

- `system` follows the operating system.
- `reduced` removes movement and scaling but keeps short fades.
- `disabled` removes fades too.

Components read it through `useMotionPreference()`. The provider also renders a `display: contents`
scope carrying `data-ds-motion` and `data-motion-profile`, so CSS press effects and disabled
transitions follow the same setting without per-control attributes. Nested providers override
their own scope; overlays carry it across portals. Wrap an app or a flow-content region with the
provider, rather than placing it directly inside a table, list or select.

CSS animations also use `motion-reduce:` for the operating system preference. Entering and exiting
overlays fade when movement is reduced.
