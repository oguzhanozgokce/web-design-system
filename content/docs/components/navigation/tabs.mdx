## Usage

```tsx
import { Tab, TabList, TabPanel, Tabs } from '@/components/ds/tabs';

<Tabs>
  <TabList aria-label="Project">
    <Tab id="overview">Overview</Tab>
    <Tab id="activity">Activity</Tab>
  </TabList>
  <TabPanel id="overview">…</TabPanel>
  <TabPanel id="activity">…</TabPanel>
</Tabs>;
```

Each `Tab` and its `TabPanel` share an `id`. Give every `TabList` an `aria-label` that names what
the tabs switch between.

## Examples

### Variants

`primary` tabs sit at the top of a page or a large section; the 3px indicator is as wide as the
label. `secondary` tabs split content inside a section; the 2px indicator spans the whole tab.
`pill` is for compact filters inside a card or a toolbar. The indicator slides to the new tab on the
spatial spring, mirrored in right-to-left languages, and jumps without motion under reduced motion.

<ComponentPreview name="tabs-variants" align="start" />

### Icons

`icon` takes any icon. Primary tabs stack it above the label, as Material 3 does; secondary and pill
tabs put it before the label. Set `iconPlacement="start"` on `Tabs` to keep primary tabs at 48px.
`fullWidth` shares the width equally, which suits three or four short tabs on a narrow screen.

<ComponentPreview name="tabs-icons" align="start" />

### Badges

`badge` takes a number, `true` for a dot, or your own [Badge](/docs/components/feedback/badge) for
another tone or label. Numbers render as a Badge: they are formatted for the locale, cap at 99+,
hide at zero and are announced as "12 new" in the reader's language. On a stacked primary tab or an
icon-only tab the badge sits on the icon.

<ComponentPreview name="tabs-badges" align="start" />

### Scrolling

When the tabs do not fit, the list scrolls and fades out at the edge that has more tabs. Selecting a
tab, by pointer or keyboard, scrolls it fully into view. Use `items` for dynamic lists.

<ComponentPreview name="tabs-scrollable" align="start" />

### Vertical

`orientation="vertical"` puts the tabs beside the panel, for settings pages and wide admin layouts.
The indicator moves to the edge that faces the panel, and Up and Down arrows move between tabs.
Vertical tabs need width, so this example switches to horizontal below 40rem with `useMediaQuery`.

<ComponentPreview name="tabs-vertical" align="start" />

### Pill filters

`variant="pill"` has no divider, so it fits a card header. Keep the labels to one or two words.

<ComponentPreview name="tabs-pill" />

### Disabled

`disabledKeys` on `Tabs`, or `isDisabled` on a `Tab`, takes a tab out of the keyboard order. Say
near the tabs why it is unavailable. `isDisabled` on `Tabs` disables them all and greys out the
indicator.

<ComponentPreview name="tabs-disabled" align="start" />

### Controlled

`selectedKey` and `onSelectionChange` control the selection, so other buttons can move between tabs.
`defaultSelectedKey` sets the first tab shown when the tabs are uncontrolled.

<ComponentPreview name="tabs-controlled" align="start" />

## API

### Tabs

| Prop                 | Type                                 | Default                                        |
| -------------------- | ------------------------------------ | ---------------------------------------------- |
| `variant`            | `'primary' \| 'secondary' \| 'pill'` | `'primary'`                                    |
| `orientation`        | `'horizontal' \| 'vertical'`         | `'horizontal'`                                 |
| `iconPlacement`      | `'top' \| 'start'`                   | `'top'` for horizontal primary, else `'start'` |
| `fullWidth`          | `boolean`                            | `false`                                        |
| `selectedKey`        | `Key \| null`                        |                                                |
| `defaultSelectedKey` | `Key`                                | first tab                                      |
| `onSelectionChange`  | `(key: Key) => void`                 |                                                |
| `disabledKeys`       | `Iterable<Key>`                      |                                                |
| `isDisabled`         | `boolean`                            | `false`                                        |
| `keyboardActivation` | `'automatic' \| 'manual'`            | `'automatic'`                                  |

Every other [React Aria Tabs](https://react-aria.adobe.com/Tabs) prop is passed through. Vertical
tabs always place icons at the start.

### TabList

| Prop         | Type                                  | Default |
| ------------ | ------------------------------------- | ------- |
| `aria-label` | `string`                              |         |
| `items`      | `Iterable<T>`                         |         |
| `children`   | `ReactNode \| (item: T) => ReactNode` |         |
| `className`  | `string`                              |         |

`className` styles the outer container that holds the divider and the scrolling area. `ref` points
at the element with `role="tablist"`.

### Tab

| Prop         | Type                             | Default |
| ------------ | -------------------------------- | ------- |
| `id`         | `Key`                            |         |
| `icon`       | `ReactNode`                      |         |
| `badge`      | `number \| boolean \| ReactNode` |         |
| `isDisabled` | `boolean`                        | `false` |
| `href`       | `string`                         |         |
| `aria-label` | `string`                         |         |

With `href`, the tab renders as a link and navigates through `DSProvider`'s router; give the matching
`TabPanel` the page content. A tab without a text label must have an `aria-label` or
`aria-labelledby`; the types require one.

### TabPanel

| Prop               | Type      | Default |
| ------------------ | --------- | ------- |
| `id`               | `Key`     |         |
| `shouldForceMount` | `boolean` | `false` |

A panel fades in when it is selected, and is instant when motion is disabled in `DSProvider`.

### Data attributes

Tabs: `data-slot="tabs"`, `data-variant`, `data-orientation`, `data-icon-placement`,
`data-full-width`, `data-disabled`.

Tab: `data-selected`, `data-hovered`, `data-pressed`, `data-focus-visible`, `data-disabled`,
`data-stacked`.

Parts: `data-slot="tab-list-container"`, `"tab-scroller"`, `"tab-list"`, `"tab"`, `"tab-content"`,
`"icon"`, `"label"`, `"indicator-track"` (horizontal tabs), `"indicator"` and `"tab-panel"`. The
scroller carries `data-overflow-start` and `data-overflow-end` while tabs are hidden on that side.
Badges are Badge's own parts: `data-slot="badge"`, and `"badge-anchor"` when the badge sits on the
icon.

### Labels

Tabs writes no text of its own, so it takes no `labels`. A badge on a tab reads its hidden label
from Badge's [labels](/docs/components/feedback/badge#labels), which you set app-wide with
`<DSProvider labels={{ badge: { … } }}>`.

## Accessibility

- Built on React Aria `Tabs`: the list is one tab stop, arrow keys move between tabs and are
  mirrored in right-to-left languages, and Home and End jump to the ends. With the default
  `keyboardActivation="automatic"` the arrow keys also select; `manual` waits for Enter or Space.
- Tabs and panels are linked with `aria-controls` and `aria-labelledby`. A panel with nothing
  focusable inside becomes focusable itself, so keyboard users can reach its content.
- The indicator is decorative. Selection is announced through `aria-selected` and shown by the
  label colour as well as the indicator.
- Badges carry a hidden, localised label ("12 new", or "New" for the dot) that is read after the
  tab's label, also on stacked tabs where the badge sits on the icon.
- Contrast is checked with axe in light, dark and RTL by `tabs.test.tsx`.
