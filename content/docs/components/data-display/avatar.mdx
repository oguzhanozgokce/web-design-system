## Usage

```tsx
import { Avatar, AvatarGroup } from '@/components/ds/avatar';

<Avatar name={member.name} src={member.photoUrl} status="online" />;

<AvatarGroup aria-label="Project members" max={3}>
  {members.map((member) => (
    <Avatar key={member.id} name={member.name} src={member.photoUrl} />
  ))}
</AvatarGroup>;
```

Always pass `name`, even with a photo. It names the avatar for screen readers and gives the
initials that show while the photo loads or when it fails.

## Examples

### Fallbacks

The photo fades in over 250 ms once it has loaded. Until then, and for good if it fails, the avatar shows the
initials of `name`. Without a name it shows a person glyph; `fallbackIcon` swaps the glyph, for a
team or a bot. A photo that loaded before hydration is picked up too, so server-rendered pages do
not get stuck on initials.

<ComponentPreview name="avatar-fallbacks" />

### Initials

Initials are the first letter of the first and last word, so middle names are skipped. Words that
start with punctuation, such as `(Design)`, are ignored. Scripts without capital letters (Arabic,
Chinese, Japanese, Korean, Thai and others) get one character, and a character is always a whole
grapheme, so combining marks and conjuncts stay intact. Initials are uppercased in the
`DSProvider` locale, including languages with different uppercase forms of the same letter.

<ComponentPreview name="avatar-initials" />

### Tones

Initials and the glyph sit on a translucent `neutral-soft` fill in `on-surface`, the same quiet fill
for everyone, so a list of people stays calm and the accent is left for what it means. `tone`
paints the fallback with a soft role and its `on-` partner instead: `primary` to pick out the
current user or an owner, and `success`, `warning`, `error` or `info` when the avatar stands for a
service or a status rather than a person. A photo covers the tone once it loads.

<ComponentPreview name="avatar-tones" />

### Sizes

`md` (40px) is the default. `xs` (24px) fits table cells and inline mentions, `sm` (32px) dense
lists and comment threads, `lg` (48px) list headers and `xl` (64px) profile headers. Initials are
medium weight at 12px for `xs` and `sm`, 14px for `md`, 16px for `lg` and 20px for `xl`.

<ComponentPreview name="avatar-sizes" />

### Shapes

`circle` is for people. `rounded` is for teams, projects and albums, so the two never get confused
in the same list. Its corners are 8px up to `sm` and 12px from `md` up.

<ComponentPreview name="avatar-shapes" />

### Status

`status` adds a presence dot at the bottom-end corner, from left to right here: `online`, `away`,
`busy` and `offline`. The first three use the solid success, warning and error fills; `offline` is
a grey ring. Each has its own shape as well as its own colour, so it reads without colour vision,
and screen readers hear the status after the name.

<ComponentPreview name="avatar-status" />

### Next to a visible name

When the name is already written beside the avatar, pass `alt=""`. The image is then hidden from
screen readers so they do not read the name twice. A `status` is still announced, because the text
beside the avatar does not say it.

<ComponentPreview name="avatar-decorative" />

### Group

`AvatarGroup` overlaps its avatars by a quarter of their size, shows the first `max` (4 by default)
and sums up the rest in a neutral `+N` avatar that screen readers hear as “N more”. It sets `size`
(default `sm`) and `shape` for every avatar inside it, and stacks from the start edge in
right-to-left languages. Leave `status` off avatars in a group: the next avatar covers the dot.

<ComponentPreview name="avatar-group" />

### Counting from the server

When you load only the first few members, pass the real count as `total`. Above 99 the overflow
avatar shows `99+`, while screen readers still hear the exact number.

<ComponentPreview name="avatar-group-total" />

### Seams

By default each avatar in a group is cut out of the one before it with a 2px ring in the `canvas`
colour, and status dots use the same ring. Inside an `outline` or `elevated` Card the ring takes the
card's surface on its own; on any other solid surface, set `--ds-avatar-ring` to that role once on
the container. Over a photo, a gradient or a translucent fill no solid colour matches, so pass
`seam="clip"`: a mask cuts a 2px transparent gap into each avatar where the next one overlaps, and
whatever is behind shows through. A focused avatar button drops the mask so its focus ring stays
whole.

<ComponentPreview name="avatar-group-surface" />

### As a button

`AvatarButton` is a React Aria `Button` with the same props as `Avatar`. Use it to open a profile,
assign someone or trigger an account menu: it works as the trigger of `MenuTrigger`,
`DialogTrigger`, `TooltipTrigger` and popovers. Hovering lays a translucent neutral overlay on the
avatar, pressing darkens it a step and scales it to 96%, and a disabled button shows at half
opacity. Give it an `aria-label` that says what pressing does.

<ComponentPreview name="avatar-button" />

```tsx
<MenuTrigger>
  <AvatarButton name={user.name} src={user.photoUrl} aria-label="Account" />
  <Menu>…</Menu>
</MenuTrigger>
```

## API

### Avatar

| Prop           | Type                                                                    | Default      |
| -------------- | ----------------------------------------------------------------------- | ------------ |
| `name`         | `string`                                                                |              |
| `alt`          | `string`                                                                | `name`       |
| `src`          | `string`                                                                |              |
| `imageProps`   | `ImgHTMLAttributes` without `src` and `alt`                             |              |
| `fallbackIcon` | `ReactNode`                                                             | person glyph |
| `size`         | `'xs' \| 'sm' \| 'md' \| 'lg' \| 'xl'`                                  | `'md'`       |
| `shape`        | `'circle' \| 'rounded'`                                                 | `'circle'`   |
| `tone`         | `'neutral' \| 'primary' \| 'success' \| 'warning' \| 'error' \| 'info'` | `'neutral'`  |
| `status`       | `'online' \| 'away' \| 'busy' \| 'offline'`                             |              |
| `labels`       | `Partial<AvatarLabels>`                                                 |              |

`alt`, `aria-label` or `aria-labelledby` overrides the accessible name. An empty `alt`, or no name
at all, hides the image from screen readers; its `status` is still announced. Use `imageProps` for
`srcSet`, `sizes`, `loading`, `referrerPolicy` and `onError`. Every other `span` attribute is passed
to the root. Inside an `AvatarGroup`, `size` and `shape` default to the group's.

### AvatarButton

`name`, `alt`, `src`, `imageProps`, `fallbackIcon`, `size`, `shape`, `tone`, `status` and `labels`
as on `Avatar`, plus every [React Aria Button](https://react-aria.adobe.com/Button) prop such as
`onPress`, `isDisabled` and `aria-label`. React Aria's `name` and `value` form props are left out,
because `name` is the person's name here. `isPending` is left out too.

### AvatarGroup

| Prop       | Type                                   | Default            |
| ---------- | -------------------------------------- | ------------------ |
| `children` | `Avatar` or `AvatarButton` elements    |                    |
| `max`      | `number`                               | `4`                |
| `total`    | `number`                               | number of children |
| `size`     | `'xs' \| 'sm' \| 'md' \| 'lg' \| 'xl'` | `'sm'`             |
| `shape`    | `'circle' \| 'rounded'`                | `'circle'`         |
| `seam`     | `'ring' \| 'clip'`                     | `'ring'`           |
| `labels`   | `Partial<AvatarLabels>`                |                    |

`max` counts avatars, not the overflow avatar. Give the group an `aria-label`, such as “Project
members”.

### Helpers

`getAvatarInitials(name, locale?)` is exported for places that need the same initials outside an
avatar.

### Data attributes

Avatar: `data-slot="avatar"`, `data-size`, `data-shape`, `data-tone`, `data-status`,
`data-image-state` (`loading`, `loaded`, `error`; only with `src`). Parts: `"avatar-visual"`,
`"avatar-image"` (with `data-loaded`), `"avatar-initials"`, `"avatar-icon"`, `"avatar-status"`.
AvatarButton: `data-slot="avatar-button"`, `data-size`, `data-shape` and React Aria's `data-hovered`,
`data-pressed`, `data-focus-visible` and `data-disabled`. AvatarGroup: `data-slot="avatar-group"`,
`data-size`, `data-shape`, `data-seam`, with `"avatar-group-item"` and `"avatar-overflow"`. `avatarStyles`,
`avatarGroupStyles` and `avatarButtonStyles` expose the classes. `--ds-avatar-ring` sets the
cut-out ring colour (`canvas` by default).

### Labels

Text the avatar writes on its own. Pass `labels` to one `Avatar`, `AvatarButton` or `AvatarGroup`,
or set them for every avatar with `<DSProvider labels={{ avatar: { … } }}>`.

| Key           | Default        | Used for                                        |
| ------------- | -------------- | ----------------------------------------------- |
| `online`      | `Online`       | the hidden status text after the name           |
| `away`        | `Away`         | the hidden status text after the name           |
| `busy`        | `Busy`         | the hidden status text after the name           |
| `offline`     | `Offline`      | the hidden status text after the name           |
| `more`        | `{count} more` | the accessible name of the `+N` overflow avatar |
| `overflowCap` | `{max}+`       | what the overflow avatar shows above 99 hidden  |

`{count}` and `{max}` arrive formatted with the locale's number format. A template can also be a
function of those values, for languages with plural forms: `more: ({ count }) => …`. One person's
status can say more than the status, such as `labels={{ busy: 'In a meeting until 14:00' }}`.

## Accessibility

- An avatar is one image named after the person (`role="img"`), whether it shows a photo, initials
  or the glyph, so screen readers hear the same thing while the photo loads. Initials are never
  read out on their own and are not machine-translated.
- The status is visually hidden text after the image, taken from `labels`, and stays announced
  when the image is decorative. The dot also differs in shape (filled, crescent, bar, ring), not
  only in colour.
- `AvatarGroup` is a labelled `group`; the overflow avatar is read as “3 more”, not “+3”.
- `AvatarButton` gets its name from the avatar and status unless you set `aria-label`. On touch
  screens, `xs`, `sm` and `md` grow their hit area to 48px without changing the layout. Pressing
  scales it slightly and the group's avatars scale in; both only play when spatial motion is on, so
  a reduced-motion setting in the system or in `DSProvider` turns them off. The photo fade turns
  off with the system setting or `motion="disabled"`.
