## Usage

```tsx
import { IconButton } from '@/components/ds/icon-button';
import { Menu, MenuItem, MenuSeparator, MenuTrigger } from '@/components/ds/menu';
import { DeleteIcon, EditIcon, MoreVerticalIcon } from '@/lib/ds/icons';

<MenuTrigger>
  <IconButton aria-label="More actions" icon={<MoreVerticalIcon />} />
  <Menu onAction={(key) => runAction(key)}>
    <MenuItem id="edit" startIcon={<EditIcon />} shortcut={['mod', 'E']}>
      Edit
    </MenuItem>
    <MenuSeparator />
    <MenuItem id="delete" startIcon={<DeleteIcon />} tone="error">
      Delete
    </MenuItem>
  </Menu>
</MenuTrigger>;
```

`MenuTrigger` takes two children: a pressable trigger such as `Button` or `IconButton`, and a
`Menu`. `Menu` draws the popover surface and the list. `onAction` on the menu receives the `id` of
the chosen item; each `MenuItem` also takes its own `onAction`. The menu closes as soon as an
action runs, so work that takes a while reports its progress somewhere else, such as a toast.

## Examples

### Descriptions

`description` adds a second line under the label. Use it when the label alone leaves people
guessing, such as which export format suits which tool. Keep it to a few words: the description is
part of what screen readers announce for the item.

<ComponentPreview name="menu-descriptions" />

### Keyboard shortcuts

`shortcut` shows the key combination that also runs the action, at the end of the row in small grey
text. It is a ghost [KbdCombo](/docs/components/data-display/kbd), so it follows the platform the
same way: `'mod'` is ⌘ on Apple platforms and Ctrl elsewhere, Apple platforms show symbols in
Apple's modifier order (⌃ ⌥ ⇧ ⌘) with no separator, and elsewhere the keys are joined with `+`,
such as `Ctrl+Shift+S`, which an app can shorten to `Ctl+Shft+S` through the menu's
[labels](#labels). Named keys are `mod`, `command`, `control`, `option`, `alt`, `shift`, `enter`,
`backspace`, `delete`, `escape`, `tab`, `space` and the four arrows; any other string, such as `'Z'`
or `'F2'`, renders as written, with single letters in capitals. The menu only shows the hint:
register the shortcut yourself.

<ComponentPreview name="menu-shortcuts" />

### Sections

Group related items with `MenuSection` and give each group a `MenuHeader`. A section without a
header needs an `aria-label`. Put a `MenuSeparator` between sections.

<ComponentPreview name="menu-sections" />

### Selection

`selectionMode="single"` or `"multiple"` on a `Menu` or a `MenuSection` turns items into radio or
checkbox items. Their labels move in to make room for a check mark at the start, drawn in
`primary`; the label itself stays in the normal text colour. Each section keeps its own selection,
so one menu can hold a sort order and a set of visible columns. Single selection closes the menu; multiple
selection keeps it open so people can tick several items.

<ComponentPreview name="menu-selection" />

### Dynamic items

Pass `items` and a function as children to render a menu from data. Each item needs an `id`, and
`disabledKeys` turns individual items off without changing the data.

<ComponentPreview name="menu-dynamic" />

### Submenus

`SubmenuTrigger` takes a `MenuItem` and a `Menu`. The submenu opens on hover after 200 ms, with
the arrow key that points into it, or with Enter, and it inherits the parent's `size` and
`labels`. Keep nesting to two levels; deeper paths are easier as a dialog.

On screens wider than 30rem (480px) a submenu opens beside its parent. Up to that width two menus
side by side do not fit, so the submenu drops below the item that opened it instead, indented 16px
towards the reading direction and over the items further down. The item stays visible above it,
the popover carries `data-stacked`, and the keyboard works the same in both layouts.

<ComponentPreview name="menu-submenu" />

### Links

An item with `href` renders an anchor. Internal links navigate through `DSProvider`'s router, so
next-intl locale prefixes keep working. Say in the description when a link opens a new tab.

<ComponentPreview name="menu-links" />

### Disabled items

`isDisabled` on an item or `disabledKeys` on the menu keeps the item visible but skips it with the
arrow keys. Say why it is unavailable in the `description` rather than hiding it.

<ComponentPreview name="menu-disabled" />

### Sizes

`md` rows are at least 36px tall with 14px text and 16px icons. `sm` rows are 32px, for admin tables
and toolbars. Rows have 12px corners inside the 16px popover, which has 4px of padding, so the
corners stay concentric. This example renders `MenuList` inline so both sizes are visible at
once.

<ComponentPreview name="menu-sizes" />

### Context menu

`trigger="contextMenu"` opens the menu at the pointer on right click, on long press on touch
screens, with Shift+F10 or the Menu key on Windows and Linux, with Control+Enter on macOS and with
the screen reader's context menu command. The trigger keeps its own `onPress`. A context menu is
hard to discover, so offer the same actions from a visible button as well.

<ComponentPreview name="menu-context" />

### Custom content

`Menu` is `MenuPopover` with a `MenuList` inside. Compose the two yourself to put content above the
list, such as the signed-in account. Only the list is keyboard navigable, so keep the extra content
to text.

## API

### MenuTrigger

React Aria [MenuTrigger](https://react-aria.adobe.com/Menu). Its first child must be a pressable
component.

| Prop           | Type                                      | Default   |
| -------------- | ----------------------------------------- | --------- |
| `trigger`      | `'press' \| 'longPress' \| 'contextMenu'` | `'press'` |
| `isOpen`       | `boolean`                                 |           |
| `defaultOpen`  | `boolean`                                 | `false`   |
| `onOpenChange` | `(isOpen: boolean) => void`               |           |

### Menu

| Prop                  | Type                                                 | Default                                |
| --------------------- | ---------------------------------------------------- | -------------------------------------- |
| `size`                | `'sm' \| 'md'`                                       | `'md'`, or the parent menu's size      |
| `onAction`            | `(key: Key, value: T) => void`                       |                                        |
| `selectionMode`       | `'none' \| 'single' \| 'multiple'`                   | `'none'`                               |
| `selectedKeys`        | `'all' \| Iterable<Key>`                             |                                        |
| `defaultSelectedKeys` | `'all' \| Iterable<Key>`                             |                                        |
| `onSelectionChange`   | `(keys: Selection) => void`                          |                                        |
| `disabledKeys`        | `Iterable<Key>`                                      |                                        |
| `items`               | `Iterable<T>`                                        |                                        |
| `shouldCloseOnSelect` | `boolean`                                            | `true`, `false` for multiple selection |
| `renderEmptyState`    | `() => ReactNode`                                    | the `empty` label                      |
| `placement`           | `'bottom start' \| 'bottom end' \| 'top start' \| …` | `'bottom start'`, submenus `'end top'` |

Up to 30rem wide, a submenu defaults to `placement="bottom start"`, `offset` `2` and a 16px
`crossOffset` instead.
| `offset` | `number` | `8`, `0` for context menus, submenus `-2` |
| `crossOffset` | `number` | `0`, submenus `-4` |
| `shouldFlip` | `boolean` | `true` |
| `maxHeight` | `number` | the space left in the viewport |
| `containerPadding` | `number` | `12` |
| `labels` | `Partial<MenuLabels>` | the parent menu's labels |

Every other [React Aria Menu](https://react-aria.adobe.com/Menu) prop is passed through to the list.
The surface is `bg-surface-overlay` with `rounded-overlay` (16px) corners, `shadow-md` and 4px of
padding, between 224px and 320px wide and never wider than the screen less 32px. Buttons in custom
content keep their own size and variant even when the trigger sits in a
[Button Group](/docs/components/actions/button-group).

### MenuItem

| Prop            | Type                   | Default                        |
| --------------- | ---------------------- | ------------------------------ |
| `id`            | `Key`                  |                                |
| `children`      | `ReactNode`            | the label                      |
| `startIcon`     | `ReactNode`            |                                |
| `description`   | `ReactNode`            |                                |
| `shortcut`      | `MenuShortcutKey[]`    |                                |
| `tone`          | `'neutral' \| 'error'` | `'neutral'`                    |
| `isDisabled`    | `boolean`              | `false`                        |
| `onAction`      | `() => void`           |                                |
| `textValue`     | `string`               | the label, when it is a string |
| `href`          | `string`               |                                |
| `target`, `rel` | `string`               |                                |
| `routerOptions` | `RouterOptions`        |                                |

Every other [React Aria MenuItem](https://react-aria.adobe.com/Menu) prop is passed through. Set
`textValue` when the label is not a plain string, so typeahead still finds the item. A long label
wraps to a second line and is clipped after that, so keep labels to a few words. The focused row
takes `bg-neutral-soft`; an `error` item has `error` text and icon and a `bg-error-soft` focus,
and keeps them when selected, its check included. A pressed row scales to 98%. A disabled item
keeps its colours at half opacity with a not-allowed cursor. The start icon is decorative and
hidden from screen readers.

### MenuSection, MenuHeader and MenuSeparator

`MenuSection` takes `selectionMode`, `selectedKeys`, `defaultSelectedKeys`, `onSelectionChange`,
`disallowEmptySelection` and `shouldCloseOnSelect` of its own, and `aria-label` when it has no
`MenuHeader`. `MenuHeader` is the section title, `text-xs font-medium` in `on-surface-variant`.
`MenuSeparator` is a 1px `outline-subtle` line inset 8px from the popover's padding.

### SubmenuTrigger

React Aria [SubmenuTrigger](https://react-aria.adobe.com/Menu). The first child is the `MenuItem`
that opens the submenu, the second is a `Menu`. `delay` sets the hover delay, 200 ms by default.

### MenuPopover and MenuList

The two parts `Menu` is made of. `MenuPopover` takes every
[React Aria Popover](https://react-aria.adobe.com/Popover) prop. `MenuList` takes every `Menu` prop
except the placement ones; rendered outside a popover it needs an `aria-label`.

### Styles

`menuPopoverStyles({ motion, className })` is the menu surface, with Popover's enter and exit
motion. `menuStyles({ size, tone, selectable })` exposes the `list`, `item`, `icon`, `content`,
`label`, `description`, `shortcut`, `check`, `submenu`, `section`, `header`, `separator` and
`empty` slots.

### Data attributes

Menu: `data-slot="menu"`, `data-size`, `data-empty`. Popover: `data-slot="menu-popover"`,
`data-placement`, `data-trigger` (`MenuTrigger` or `SubmenuTrigger`), `data-stacked` on a submenu
below its item, `data-entering`, `data-exiting`. Item: `data-slot="menu-item"`, `data-tone`, `data-size`, `data-hovered`,
`data-focused`, `data-focus-visible`, `data-pressed`, `data-selected`, `data-selection-mode`,
`data-disabled`, `data-has-submenu`, `data-open`. Parts: `data-slot="start-icon"`, `"content"`,
`"label"`, `"description"`, `"shortcut"` (with `data-platform`, holding a `"kbd-combo"`), `"check"`,
`"submenu-indicator"`,
`"menu-section"`, `"menu-header"`, `"menu-separator"`, `"empty"`.

### Labels

Text the menu writes on its own. Pass `labels` to one `Menu` or `MenuList`, which hands them to its
items and submenus, or set them for every menu with `<DSProvider labels={{ menu: { … } }}>`. The
key names are the short names shown outside Apple platforms, where keyboards print them; they
override Kbd's `*Short` [labels](/docs/components/data-display/kbd#labels) for this menu. What
screen readers hear for each key comes from Kbd's labels, so set those app-wide with
`<DSProvider labels={{ kbd: { … } }}>`.

| Key         | Default     | Used for                                    |
| ----------- | ----------- | ------------------------------------------- |
| `empty`     | `No items`  | the empty state of a menu with no items     |
| `ctrl`      | `Ctrl`      | `mod`, `control` and `ctrl` in a `shortcut` |
| `alt`       | `Alt`       | `alt` and `option` in a `shortcut`          |
| `shift`     | `Shift`     | `shift` in a `shortcut`                     |
| `enter`     | `Enter`     | `enter` in a `shortcut`                     |
| `backspace` | `Backspace` | `backspace` in a `shortcut`                 |
| `delete`    | `Del`       | `delete` in a `shortcut`                    |
| `escape`    | `Esc`       | `escape` in a `shortcut`                    |
| `tab`       | `Tab`       | `tab` in a `shortcut`                       |
| `space`     | `Space`     | `space` in a `shortcut`, on every platform  |

## Accessibility

- Built on React Aria `Menu`. The trigger gets `aria-haspopup` and `aria-expanded`. Enter, Space
  and ArrowDown open the menu on the first item, ArrowUp on the last. Arrow keys, Home, End and
  typeahead move between items, and Escape closes the menu and returns focus to the trigger.
- Submenus open with ArrowRight, or ArrowLeft in right-to-left locales, and close with the opposite
  arrow or Escape. The chevron flips with the reading direction.
- Selectable items are `menuitemradio` or `menuitemcheckbox` with `aria-checked`. The check mark is
  decorative.
- An item's accessible name starts with its label, then its description and the shortcut's key
  names, so speech input users can say what they see (WCAG 2.5.3, which axe checks). Symbols such
  as ⌘ are hidden and replaced by the spoken name, so `⌘E` is read as "Command+E". In tests, match
  items by the start of their name, such as `{ name: /^Duplicate/ }`.
- Context menus leave out `aria-haspopup`, because pressing the trigger does not open them. Offer
  the same actions from a visible button.
- Disabled items stay visible and are skipped by the arrow keys. The error tone is colour only, so
  keep the word in the label, such as "Delete", and confirm actions that cannot be undone.
- The menu grows from its trigger. With reduced motion, from the system or `DSProvider`, it fades
  instead, and pressed rows do not scale. In forced-colours mode the focused item uses the system highlight.
- The popover renders in a portal and carries the current `lang` and `dir`, so translated items
  are pronounced correctly and submenus open towards the reading direction.
- Contrast is checked with axe in light, dark and RTL by `menu.test.tsx`.
