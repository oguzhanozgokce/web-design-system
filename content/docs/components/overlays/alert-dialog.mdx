## Usage

```tsx
import { AlertDialog } from '@/components/ds/alert-dialog';
import { Button } from '@/components/ds/button';
import { DialogTrigger } from '@/components/ds/dialog';

<DialogTrigger>
  <Button tone="error">Delete file</Button>
  <AlertDialog
    tone="error"
    title="Delete “Notes.txt”?"
    description="The file is deleted for everyone it is shared with. This cannot be undone."
    confirmLabel="Delete"
    onConfirm={() => deleteFile(id)}
  />
</DialogTrigger>;
```

An alert dialog asks one question and offers two answers. It is built on
[Dialog](/docs/components/overlays/dialog) with the `alertdialog` role, so it installs Dialog too
and opens from the same `DialogTrigger`. Name the confirm button after the action ("Delete",
"Publish"), not "OK", so the choice reads on its own.

The confirm button is a solid [Button](/docs/components/actions/button), `error` with the `error`
tone and `primary` otherwise; Cancel is a `soft`, neutral one beside it.

When `onConfirm` returns a promise, as in the preview above, the confirm button shows a spinner,
Cancel is disabled, and Escape and the backdrop do nothing until the promise settles. The dialog
closes when it resolves. A synchronous `onConfirm` closes the dialog right away.

## Examples

### Failure

When the promise rejects, the dialog stays open and shows the error above the actions on a pale
error tint, where screen readers announce it. Both buttons work again, so the person can retry or cancel. The
message is `error.message` when there is one, otherwise the `error` label. Pass `errorMessage` as a
node or as `(error) => node` to write your own.

<ComponentPreview name="alert-dialog-error" />

### Tones

`tone` is `neutral` (the default), `primary`, `success`, `warning`, `info` or `error`. It tints the
icon. Every tone but `error` uses a primary confirm button, for actions that are consequential but
safe, such as publishing, and focus starts on it, so Enter confirms. `tone="error"` makes the
confirm button red and starts focus on Cancel, as does `isConfirmDisabled` with any tone.

<ComponentPreview name="alert-dialog-default" />

### Type to confirm

`requireConfirmation` adds a field and keeps the confirm button disabled until the phrase is typed
exactly. Focus starts in the field and Enter confirms once it matches, but not while an input
method is still composing. Escape and Tab work from the field as from any other control. Keep it
for actions that destroy a lot of data at once, such as a whole account.

<ComponentPreview name="alert-dialog-type-to-confirm" />

### Hero icon

`icon` sits in a 40px circle above the title, aligned to the start. The circle takes a pale tint
of the tone (`bg-error-soft` with `tone="error"`) and a translucent grey with `neutral`.

<ComponentPreview name="alert-dialog-icon" />

### Controlled

Pass `isOpen` and `onOpenChange` to open the dialog from a list row or a menu item. When the row
that opened the dialog is removed, focus has nowhere to return, so move it yourself once
`isOpen` turns false. The example focuses the list heading, which has `tabIndex={-1}`.

## API

### AlertDialog

| Prop                        | Type                                                                    | Default            |
| --------------------------- | ----------------------------------------------------------------------- | ------------------ |
| `title`                     | `ReactNode`                                                             | required           |
| `description`               | `ReactNode`                                                             |                    |
| `children`                  | `ReactNode`                                                             |                    |
| `icon`                      | `ReactNode`                                                             |                    |
| `tone`                      | `'neutral' \| 'primary' \| 'success' \| 'warning' \| 'info' \| 'error'` | `'neutral'`        |
| `confirmLabel`              | `ReactNode`                                                             | `'Confirm'`        |
| `cancelLabel`               | `ReactNode`                                                             | `'Cancel'`         |
| `onConfirm`                 | `() => void \| Promise<unknown>`                                        |                    |
| `onCancel`                  | `() => void`                                                            |                    |
| `isConfirmDisabled`         | `boolean`                                                               | `false`            |
| `requireConfirmation`       | `string`                                                                |                    |
| `errorMessage`              | `ReactNode \| ((error: unknown) => ReactNode)`                          | from the rejection |
| `labels`                    | `Partial<AlertDialogLabels>`                                            |                    |
| `size`                      | `'sm' \| 'md' \| 'lg'`                                                  | `'sm'`             |
| `isDismissable`             | `boolean`                                                               | `false`            |
| `isKeyboardDismissDisabled` | `boolean`                                                               | `false`            |
| `isOpen`                    | `boolean`                                                               | from the trigger   |
| `defaultOpen`               | `boolean`                                                               |                    |
| `onOpenChange`              | `(isOpen: boolean) => void`                                             |                    |
| `className`                 | `string`                                                                |                    |
| `overlayClassName`          | `string`                                                                |                    |

`children` render in the body, above the type-to-confirm field. `onCancel` runs when Cancel is
pressed; Escape and the backdrop close the dialog through `onOpenChange`. While `onConfirm` is
pending, `isDismissable` and Escape are switched off whatever their props say. Use `isOpen`,
`defaultOpen` and `onOpenChange` only when there is no `DialogTrigger`; with one, put them on the
trigger.

### Styling

| Part    | Classes                                                                                        |
| ------- | ---------------------------------------------------------------------------------------------- |
| icon    | Dialog's icon circle, `bg-{tone}-soft text-on-{tone}-soft`, neutral `bg-neutral-soft`          |
| confirm | `Button variant="solid"`, `tone="error"` with the error tone, `"primary"` otherwise            |
| cancel  | `Button variant="soft" tone="neutral"`                                                         |
| phrase  | `rounded-md bg-neutral-soft font-mono`                                                         |
| input   | a 40px field: `rounded-field border-outline-variant bg-surface-raised`, `border-primary` focus |
| error   | `rounded-item bg-error-soft text-sm`, the glyph in `text-on-error-soft`                        |

### Styles

`alertDialogStyles()` exposes the `icon`, `content`, `confirmation`, `label`, `phrase`, `input` and
`error` slots. The surface, header, body and footer come from `dialogStyles`.

### Data attributes

The element with the `alertdialog` role carries `data-tone` and, while `onConfirm` runs,
`data-pending`. The buttons carry `data-action="cancel"` and `data-action="confirm"` with Button's
own attributes. Parts: `data-slot="alert-dialog-icon"`, `"alert-dialog-content"`,
`"alert-dialog-confirmation"`, `"alert-dialog-label"`, `"alert-dialog-phrase"`,
`"alert-dialog-input"`, `"alert-dialog-error"`, plus the Dialog parts.

### Labels

Text the alert dialog writes on its own. The button text is content, so it stays in `confirmLabel`
and `cancelLabel`. Pass `labels` to one alert dialog, or set them for every alert dialog with
`<DSProvider labels={{ alertDialog: { … } }}>`.

| Key             | Default                            | Used for                                     |
| --------------- | ---------------------------------- | -------------------------------------------- |
| `typeToConfirm` | `Type {phrase} to confirm`         | the label of the type-to-confirm field       |
| `error`         | `Something went wrong. Try again.` | a failure whose rejection carries no message |

`typeToConfirm` is a template: a string with `{phrase}`, or a function that receives `{ phrase }`
and returns a string. The phrase is shown in a monospace chip where it appears; a template that
changes the phrase, for example by putting it in capitals, is shown as plain text without the
chip. The pending spinner takes its name from Button's labels (`button`).

## Accessibility

- The dialog has the `alertdialog` role, is named by its title and described by its
  description, so screen readers read the question when focus lands on a button.
- Focus starts on the least risky choice: Cancel with the `error` tone or while the confirm
  button is disabled, the confirm button otherwise, and the type-to-confirm field when there is
  one. It returns to the trigger on close.
- The backdrop does not close an alert dialog unless `isDismissable` is set. Escape does, except
  while the action is pending.
- While pending, the confirm button keeps focus and announces its progress bar; Cancel and the
  phrase field cannot change the outcome.
- Failures are shown in a `role="alert"` region and are never silent.
- Contrast is checked with axe in light, dark and RTL, with the type-to-confirm field and an
  error shown, by `alert-dialog.test.tsx`.
