## Usage

```tsx
import { Button } from '@/components/ds/button';
import { ButtonGroup } from '@/components/ds/button-group';

<ButtonGroup aria-label="History" size="sm" buttonVariant="soft">
  <Button onPress={undo}>Undo</Button>
  <Button onPress={redo}>Redo</Button>
</ButtonGroup>;
```

`size`, `buttonVariant`, `tone` and `isDisabled` become the defaults of every `Button`,
`ButtonLink`, `IconButton` and `CopyButton` inside the group. `ToggleButton` takes `size`,
`buttonVariant` and `isDisabled`. A prop set on a single button still wins. A `ButtonGroup` or
`ToggleButtonGroup` nested inside takes the same defaults unless it sets its own.

## Examples

### Attached

The default. The buttons touch and read as one pill: only the outer ends are round, a faint 1px
separator sits between neighbours, and the press scale is turned off so the pill never breaks
apart. Use it when the buttons act on one thing, such as moving through a calendar.

<ComponentPreview name="button-group-attached" />

### Detached

`variant="detached"` spaces the buttons 8px apart, keeps each one a pill and wraps them onto a new
line when space runs out. Use it for a few related actions that each stand on their own.

<ComponentPreview name="button-group-detached" />

### Button variant

`buttonVariant` styles every button in the group at once. All four variants work attached. Outline
buttons overlap their borders instead of drawing a separator.

<ComponentPreview name="button-group-button-variants" />

### Sizes

`size` sets the size of every button: `sm` (32px), `md` (40px, the default) or `lg` (48px). Keep
one size per group.

<ComponentPreview name="button-group-sizes" />

### Vertical

`orientation="vertical"` stacks the buttons and stretches them to the widest one. In an attached
group the top and bottom ends round by half the button height.

<ComponentPreview name="button-group-vertical" />

### Full width

`fullWidth` makes the group fill its container and shares the width equally. Detached, it suits
dialog footers and sheets on small screens.

<ComponentPreview name="button-group-full-width" align="stretch" />

### Disabled

`isDisabled` disables every button in the group. Tell people what unlocks the actions.

<ComponentPreview name="button-group-disabled" />

## API

### ButtonGroup

| Prop            | Type                                        | Default         |
| --------------- | ------------------------------------------- | --------------- |
| `variant`       | `'attached' \| 'detached'`                  | `'attached'`    |
| `orientation`   | `'horizontal' \| 'vertical'`                | `'horizontal'`  |
| `size`          | `'sm' \| 'md' \| 'lg'`                      | `'md'`          |
| `buttonVariant` | `'solid' \| 'soft' \| 'outline' \| 'ghost'` | from the button |
| `tone`          | `'primary' \| 'neutral' \| 'error'`         | from the button |
| `fullWidth`     | `boolean`                                   | `false`         |
| `isDisabled`    | `boolean`                                   | `false`         |
| `aria-label`    | `string`                                    |                 |

Every other [React Aria Group](https://react-aria.adobe.com/Group) prop is passed through.
`ToggleButton` maps `buttonVariant` onto its own two variants: `solid` and `soft` become `soft`,
`outline` and `ghost` become `ghost`.

### ButtonGroupContext

`ButtonGroupContext` is exported from `button.tsx`. A custom button can read it with `use()` to pick
up the group's `size`, `variant`, `tone` and `isDisabled`.

React context passes through portals, so a dialog or popover opened from a button in the group
inherits these defaults too. Wrap the overlay's content in `<ButtonGroupContext value={null}>` to
give its buttons their own defaults back.

### Data attributes

`data-variant`, `data-orientation`, `data-size`, `data-disabled`, `data-hovered`,
`data-focus-within`, `data-focus-visible`. Root: `data-slot="button-group"`.

## Accessibility

- Renders a React Aria `Group` with `role="group"`. Give it an `aria-label` so screen readers
  announce what the buttons belong to.
- Each button stays in the tab order. For a set of options where one or more is selected, use
  `ToggleButtonGroup`, which adds arrow-key navigation and radio or toolbar semantics.
- In an attached group the keyboard-focused button is raised above its neighbours, so no neighbour
  covers its focus ring.
- Corners and separators use logical properties, so attached groups mirror in right-to-left
  languages.
