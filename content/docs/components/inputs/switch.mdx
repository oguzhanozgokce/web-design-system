## Usage

```tsx
import { Switch } from '@/components/ds/switch';

<Switch defaultSelected onChange={setAirplaneMode}>
  Airplane mode
</Switch>;
```

A switch applies its change immediately. When the change needs a Save button, use a
[Checkbox](/docs/components/inputs/checkbox) instead.

## Examples

### Sizes

`md` (a 48 by 24px track) is the default and lines up with 40px rows. `sm` (40 by 20px) fits dense
lists and toolbars.

<ComponentPreview name="switch-sizes" />

### Description

`description` explains the consequence of turning the setting on. It is part of the click target
and is announced as the description.

<ComponentPreview name="switch-description" />

### Label placement

The label sits after the switch by default. `labelPlacement="start"` puts it first, which suits
forms where labels line up on the start edge.

<ComponentPreview name="switch-label-placement" />

### Thumb icons

The thumb is plain by default. `selectedIcon` and `unselectedIcon` put a small icon on it for each
state, such as a check and a cross, or a sun and a moon for a theme switch. The selected icon takes
the primary colour; the unselected one is a neutral grey that stays readable on the light thumb in
both themes.

<ComponentPreview name="switch-icons" />

### Settings row

`variant="row"` stretches the switch across its container with the label and description at the
start and an optional `icon`. The whole row fills with a neutral tint on hover and press. Stack rows
inside a raised surface for settings pages.

<ComponentPreview name="switch-row" align="stretch" />

### Controlled

Use `isSelected` and `onChange` when the rest of the page reacts to the setting.

<ComponentPreview name="switch-controlled" />

### Disabled

Disabled switches are drawn at half opacity with a not-allowed cursor and keep their state
visible, so people can still see how a setting is set.

## API

### Switch

| Prop              | Type                                                       | Default     |
| ----------------- | ---------------------------------------------------------- | ----------- |
| `children`        | `ReactNode`                                                |             |
| `description`     | `ReactNode`                                                |             |
| `errorMessage`    | `ReactNode \| (validation: ValidationResult) => ReactNode` |             |
| `variant`         | `'default' \| 'row'`                                       | `'default'` |
| `size`            | `'sm' \| 'md'`                                             | `'md'`      |
| `labelPlacement`  | `'start' \| 'end'`                                         | `'end'`     |
| `icon`            | `ReactNode`                                                |             |
| `selectedIcon`    | `ReactNode`                                                |             |
| `unselectedIcon`  | `ReactNode`                                                |             |
| `isSelected`      | `boolean`                                                  |             |
| `defaultSelected` | `boolean`                                                  | `false`     |
| `onChange`        | `(isSelected: boolean) => void`                            |             |
| `isDisabled`      | `boolean`                                                  | `false`     |
| `isReadOnly`      | `boolean`                                                  | `false`     |
| `isInvalid`       | `boolean`                                                  | `false`     |
| `isRequired`      | `boolean`                                                  | `false`     |

`icon` shows only in the row variant, and the row variant always puts the label at the start.
Every other [React Aria SwitchField](https://react-aria.adobe.com/Switch) prop is passed through,
such as `name`, `value` and `inputRef`.

### Data attributes

Root (`data-slot="switch"`): `data-variant`, `data-size`, `data-label-placement`,
`data-selected`, `data-disabled`, `data-readonly`, `data-invalid`, `data-required`. The clickable
part (`data-slot="target"`, the whole row for `variant="row"`) also has `data-hovered`,
`data-pressed` and `data-focus-visible`. The track (`data-slot="track"`) has `data-selected` and
`data-focus-visible`. Other parts: `"thumb"`, `"thumb-icon"`, `"icon"`, `"content"`, `"label"`,
`"required"`, `"description"`, `"error"`.

### Labels

Switch writes no text of its own, so it takes no `labels`.

## Accessibility

- Built on React Aria `SwitchField`: a native checkbox input with `role="switch"`, Space to
  toggle, and the label and description wired with `aria-labelledby` and `aria-describedby`. An
  explicit `aria-label` or `aria-labelledby` always wins over the visible label.
- The focus ring is a 2px outline around the track, or inside the whole row for `variant="row"`.
  A read-only switch shows no hover or press feedback.
- The on track uses the solid primary, which stays saturated in dark mode; the off track is an
  opaque grey so the off state is visible on any surface.
- The thumb moves with logical `inset-inline-start`, so it travels right to left in RTL without
  extra code. It slides over 300ms on the fluid curve and widens by 4px while pressed; with reduced
  motion it moves instantly.
