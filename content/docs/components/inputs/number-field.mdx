## Usage

```tsx
import { NumberField } from '@/components/ds/number-field';

<NumberField label="Quantity" defaultValue={5} minValue={1} maxValue={99} />;
```

Label, description, errors, variants and the required indicator follow the
[Field](/docs/components/inputs/field) contract. `onChange` receives a number, and only when the
value is committed: on a step, on Enter and on blur, never on every keystroke. An empty field
reports `NaN`.

Use a number field when people know the exact number they want. When the rough position matters
more, a [slider](/docs/components/inputs/slider) is faster.

## Examples

### Layouts

`layout="stepper"` (the default) puts minus and plus inside the field on either side of the centred
value, each a full-height square divided from the value by a hairline. It suits quantities and
guest counts, where most changes are one or two steps and the buttons are the main input.
`layout="inline"` stacks two half-height chevrons at the end and leaves the value where a text field
would put it, so it lines up with the other fields in a form. Its buttons are small, so prefer the
stepper layout on touch-first screens. In both, a button tints on hover and darkens while pressed.
`layout="compact"` is a small slab that hugs its number, described [below](#compact).

<ComponentPreview name="number-field-layouts" />

### Compact

`layout="compact"` is a quantity stepper for cards, list rows and carts: a slab with a small inset
that holds two soft square keys and the number between them. The keys sit concentric in the
slab's corner, sink slightly while pressed, and the slab is only as wide as the number it shows.
When a digit arrives, as in 9 to 10, the slab widens with it while the digits roll, and narrows
again when one leaves. Holding a key repeats the step, and the number is still a text box: click
or tab into it and type, and the slab fits what is typed. Compact fields roll by default; pass
`isAnimated={false}` to turn that off.

<ComponentPreview name="number-field-compact" />

The slab is 32, 40 or 48 px tall, like every field, with keys of 24, 30 and 38 px. Use `sm` in
list rows and table cells, `md` in cards, and `lg` where the quantity is the main choice on the
screen.

<ComponentPreview name="number-field-compact-sizes" />

In a list, give each field an `aria-label` that names its row, so the keys read as "Increase Prints,
10 × 15 cm" rather than a run of identical buttons. A [rolling number](/docs/components/data-display/rolling-number)
for the total keeps the summary moving with the rows.

<ComponentPreview name="number-field-compact-list" />

### Formats

`formatOptions` takes any `Intl.NumberFormat` option. Currency, percent and units such as
`kilogram` or `minute` are formatted for the locale, so `24` reads `€24.00` in English and
`24,00 €` in German, and typed input is parsed the same way. With `style: 'percent'`, the value
is a fraction: `0.8` shows as `80%`. The on-screen keyboard switches to a decimal or numeric pad to
match.

<ComponentPreview name="number-field-formats" />

### Limits and steps

`minValue` and `maxValue` clamp the value, and `step` rounds it when it is committed. The minus
or plus button fades to half opacity at each limit. Arrow keys step, Home and End jump to the
limits, and the scroll wheel steps while the field has focus. Holding a button repeats the step after 400 ms
(600 ms on touch), then every 60 ms.

<ComponentPreview name="number-field-steps" />

### Sizes

`md` (40 px) is the default. `sm` (32 px) suits table rows and filter bars, `lg` (48 px) suits
sign-up forms and touch screens. The stepper buttons are as wide as the field is tall. In the stepper
and inline layouts each size has a minimum width that fits about eight characters; set a width
with `className` for longer values. The compact layout fits its number instead.

<ComponentPreview name="number-field-sizes" />

### Large

For screens where the number is the main choice, such as copies to print or a number of guests,
use `size="lg"`: 48 px buttons are comfortable touch targets, and `isAnimated` makes each step
visible.

<ComponentPreview name="number-field-large" />

### Soft

`variant="soft"` draws the field as a borderless neutral tint, for toolbars, list rows and other
places where a bordered box would add one more line. The buttons sit inside the tint and darken it on
hover. It takes every size and layout.

<ComponentPreview name="number-field-soft" />

### Animated

`isAnimated` shows the value as a [rolling number](/docs/components/data-display/rolling-number)
while nobody is typing in the field, so each step rolls like an odometer: every column counts
forward through its carry, the ones first and each column to the left a beat later, on the
library's spatial spring for the current motion profile. The input underneath keeps the real value,
so typing, selection, screen readers and forms work as usual: the moment someone types, the plain
input shows, and a typed value appears without rolling when it is committed. It rolls in every
locale, including right-to-left ones and those with their own digits, such as Arabic-Indic digits
in `ar-EG`. Under reduced motion and in forced-colours mode the field shows plain text instead, and
so it does while the text in the box is not what the formatter would write, such as Latin digits
typed into an `ar-EG` field. The compact layout rolls by default; the others need `isAnimated`.

<ComponentPreview name="number-field-animated" />

### Variants

`outline` is the default and `soft` the tinted alternative, as on every
[Field](/docs/components/inputs/field); pick one per form.

<ComponentPreview name="number-field-variants" />

### Validation

Required fields, `validate` and `isInvalid` work as on every [Field](/docs/components/inputs/field).
By default a typed value is snapped to the nearest step and clamped to the limits on commit. Set
`commitBehavior="validate"` to keep what was typed and report it instead; the validation result
then has `stepMismatch`, `rangeOverflow` and `rangeUnderflow` for a precise `errorMessage`.

## API

### NumberField

| Prop                 | Type                                       | Default                         |
| -------------------- | ------------------------------------------ | ------------------------------- |
| `value`              | `number`                                   |                                 |
| `defaultValue`       | `number`                                   | `NaN`                           |
| `onChange`           | `(value: number) => void`                  |                                 |
| `minValue`           | `number`                                   |                                 |
| `maxValue`           | `number`                                   |                                 |
| `step`               | `number`                                   | `1`                             |
| `formatOptions`      | `Intl.NumberFormatOptions`                 |                                 |
| `commitBehavior`     | `'snap' \| 'validate'`                     | `'snap'`                        |
| `layout`             | `'stepper' \| 'inline' \| 'compact'`       | `'stepper'`                     |
| `size`               | `'sm' \| 'md' \| 'lg'`                     | `'md'`                          |
| `variant`            | `'outline' \| 'soft'`                      | `'outline'`                     |
| `isAnimated`         | `boolean`                                  | `true` in compact, else `false` |
| `placeholder`        | `string`                                   |                                 |
| `isWheelDisabled`    | `boolean`                                  | `false`                         |
| `incrementAriaLabel` | `string`                                   |                                 |
| `decrementAriaLabel` | `string`                                   |                                 |
| `inputRef`           | `Ref<HTMLInputElement>`                    |                                 |
| `labels`             | `Partial<NumberFieldLabels & FieldLabels>` |                                 |
| `className`          | `string \| ((renderProps) => string)`      |                                 |

Plus the [shared Field props](/docs/components/inputs/field#shared-props) and every other [React Aria NumberField](https://react-aria.adobe.com/NumberField)
prop, such as `name`, `validate`, `onBlur` and `isDisabled`. `className` styles the root.

### numberFieldStyles

`numberFieldStyles(variants)` returns one class function per slot: `container`, `value`, `input`,
`roller`, `sizer`, `steppers` and `stepper`. They add to the [Field](/docs/components/inputs/field#fieldstyles)
slots. Variants: `layout`, `size` and `isRolling`; the outline or soft frame comes from
`fieldStyles`.

### Data attributes

The root has `data-slot="number-field"`, `data-layout`, `data-size`, `data-variant` (`outline` or
`soft`), `data-animated`, `data-invalid`, `data-disabled`, `data-readonly` and `data-required`. The
buttons
are `data-slot="decrement"` and `"increment"` with `data-pressed` and `data-disabled`; in the inline
layout they sit in `data-slot="steppers"`. The input and the animated number sit in
`data-slot="value"`; the animated number is `data-slot="roller"`, and the input has `data-rolling`
while it shows. In the compact layout an invisible `data-slot="sizer"` copy of the text sets the
slab's width while someone types or motion is reduced. The other parts are listed on [Field](/docs/components/inputs/field#data-attributes).

### Labels

Set `labels` locally or `<DSProvider labels={{ numberField: { … } }}>` app-wide.

| Key        | Default            | Used for                                        |
| ---------- | ------------------ | ----------------------------------------------- |
| `increase` | `Increase {label}` | the accessible name of the plus or up button    |
| `decrease` | `Decrease {label}` | the accessible name of the minus or down button |

`{label}` is the field's label or `aria-label`, so screen readers hear "Increase Quantity". Put
`{label}` where the app needs it: `'{label}: increase'` names a Quantity button "Quantity: increase".
When the label is not plain text, the button is
named by reference to the label element in the same order. `incrementAriaLabel` and
`decrementAriaLabel` replace the whole name for one field. `labels` also takes the
[Field labels](/docs/components/inputs/field#labels), which `DSProvider` sets under `field`.

## Accessibility

- Built on React Aria `NumberField`: the input is a text box announced as a number field, with the
  label, description and error wired to it. Each step is announced, and so is a typed value that
  is reformatted when it is committed.
- The buttons stay out of the tab order, so keyboard users step with the arrow keys. A mouse press
  moves focus to the input; a touch press keeps it on the button so the on-screen keyboard stays
  closed. Each button is named from the field's label, in the word order of the `increase` and
  `decrease` labels, and turns off at the limits.
- The animated number is hidden from assistive technology; the input it covers keeps the value,
  the caret and the selection. Under reduced motion the keys of the compact layout do not sink when
  pressed and the value changes without rolling.
- Stepper buttons are as large as the field is tall: 32, 40 or 48 px. The compact keys are 24, 30
  and 38 px, at least the 24 px minimum target, with the slab's inset around them. The inline
  chevrons are half the field's height, which is why that layout suits forms used with a keyboard;
  the input itself takes typing and the arrow keys. A disabled field fades once as a whole; its buttons do not fade again.
