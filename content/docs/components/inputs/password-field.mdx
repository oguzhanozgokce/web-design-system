## Usage

```tsx
import { PasswordField } from '@/components/ds/password-field';

<PasswordField label="Password" name="password" isRequired />;
```

Label, description, errors, sizes and variants follow the [Field](/docs/components/inputs/field)
contract. Leave the field uncontrolled where you can: the password then lives only in the input, and
the form reads it on submit. A controlled field may reject or rewrite a keystroke in `onChange`, and
the input follows the value you keep.

## Examples

### Sign in

The default `autoComplete` is `current-password`, which lets password managers fill the field. Give
the account field `autoComplete="username"` next to it. The eye button reveals the password and its
tooltip says "Show password" or "Hide password". Turning Caps Lock on while the field has focus shows
a warning under it. The field hides the password again when its form submits or resets.

<ComponentPreview name="password-field-sign-in" />

### Requirements checklist

`rules` takes a list of `{ label, test }`. Each rule is tested on every change, and again when
`rules` itself changes, and shown as met or not met; the meter fills with the share of rules met. The checklist describes the input, so
screen readers read the requirements when it gains focus, and a polite announcement lists what
changed once typing pauses. With `rules` or `strength`, `autoComplete` defaults to `new-password`.
Keep labels short and unique; they are the list keys. A rule can close over account data, as the
name rule here does.

<ComponentPreview name="password-field-rules" />

### Strength meter

`strength` takes a score from 0 to 4 from your own estimator, such as zxcvbn, and shows it as four
rounded segments with a label from "Too weak" to "Strong". Filled segments use the solid error,
warning and success roles, which stay saturated in dark mode; empty ones are a neutral tint. Scores outside that range are rounded and clamped. Store only the score from `onChange`, as this
example does, not the password. An empty field always shows an empty meter.

<ComponentPreview name="password-field-strength" />

### Confirm a new password

`validate` and `minLength` work as on any React Aria field. Keep the new password in state with
`value` and `onChange` and compare against it in the confirmation's `validate`, so the check runs
again when either field changes. Errors show when the form is submitted.

<ComponentPreview name="password-field-confirm" />

### Variants and sizes

`outline` and `soft` in `sm`, `md` and `lg`, as on every input. The reveal button is a small round
ghost button inside the field that tints on hover. `defaultRevealed` suits a password that people
read aloud, such as a guest Wi-Fi password.

## API

### PasswordField

| Prop                  | Type                                         | Default                     |
| --------------------- | -------------------------------------------- | --------------------------- |
| `value`               | `string`                                     |                             |
| `defaultValue`        | `string`                                     | `''`                        |
| `onChange`            | `(value: string) => void`                    |                             |
| `placeholder`         | `string`                                     |                             |
| `autoComplete`        | `'current-password' \| 'new-password'`       | from `rules` and `strength` |
| `isRevealed`          | `boolean`                                    |                             |
| `defaultRevealed`     | `boolean`                                    | `false`                     |
| `onRevealChange`      | `(isRevealed: boolean) => void`              |                             |
| `showCapsLockWarning` | `boolean`                                    | `true`                      |
| `strength`            | `0 \| 1 \| 2 \| 3 \| 4`                      |                             |
| `rules`               | `PasswordRule[]`                             |                             |
| `startAdornment`      | `ReactNode`                                  |                             |
| `inputRef`            | `Ref<HTMLInputElement>`                      |                             |
| `labels`              | `Partial<PasswordFieldLabels & FieldLabels>` |                             |

Plus the [shared Field props](/docs/components/inputs/field#shared-props) and every other
[React Aria TextField](https://react-aria.adobe.com/TextField) prop, such as `name`, `minLength`,
`validate` and `onBlur`. `className` styles the root.

`PasswordRule` is `{ label: string; test: (value: string) => boolean }`. `PasswordStrength` is the
type of `strength`.

### passwordFieldStyles

`passwordFieldStyles({ level, isMet, isEmpty })` returns one class function per slot: `reveal`,
`capsLock`, `strength`, `track`, `segment`, `summary`, `strengthLabel`, `strengthValue`, `rules`,
`rule` and `ruleIcon`. `level` is the strength as a string from `'0'` to `'4'`. The reveal tooltip is
the shared [Tooltip](/docs/components/overlays/tooltip), so a `TooltipGroup` around a form sets its
delays.

### Data attributes

The root has `data-slot="password-field"`, `data-size`, `data-variant` (`outline` or `soft`),
`data-revealed`,
`data-invalid`, `data-disabled`, `data-readonly` and `data-required`. Parts:
`data-slot="reveal-button"` (with `data-selected` while revealed), `"tooltip"`, `"caps-lock"`,
`"caps-lock-announcer"`, `"strength"` (with `data-level`), `"strength-segment"` (with
`data-filled`), `"strength-value"`, `"rules"`, `"rule"` (with `data-met`) and `"announcer"`. The other parts are listed on
[Field](/docs/components/inputs/field#data-attributes).

### Labels

Text the field writes on its own. Pass `labels` to one field, or set them for every password field
with `<DSProvider labels={{ passwordField: { … } }}>`.

| Key                    | Default                          | Used for                                                          |
| ---------------------- | -------------------------------- | ----------------------------------------------------------------- |
| `showPassword`         | `Show password`                  | the reveal button's accessible name, and its tooltip while hidden |
| `hidePassword`         | `Hide password`                  | the reveal button's tooltip while the password shows              |
| `capsLockOn`           | `Caps Lock is on`                | the Caps Lock warning and its announcement                        |
| `strength`             | `Password strength`              | the meter's label                                                 |
| `strength0`            | `Too weak`                       | the meter's value at score 0                                      |
| `strength1`            | `Weak`                           | the meter's value at score 1                                      |
| `strength2`            | `Fair`                           | the meter's value at score 2                                      |
| `strength3`            | `Good`                           | the meter's value at score 3                                      |
| `strength4`            | `Strong`                         | the meter's value at score 4                                      |
| `requirements`         | `Password requirements`          | the accessible name of the checklist                              |
| `ruleMet`              | `{rule}: met.`                   | a met rule in the input's description and announcements           |
| `ruleUnmet`            | `{rule}: not met.`               | an unmet rule in the input's description and announcements        |
| `strengthAnnouncement` | `Password strength: {strength}.` | the announcement when the strength changes                        |

`{rule}` is the rule's `label` and `{strength}` the meter's value. `labels` also takes the
[Field labels](/docs/components/inputs/field#labels), which `DSProvider` sets under `field`.

## Accessibility

- The reveal control is a toggle button named "Show password" with `aria-pressed`, so screen readers
  hear "pressed" when the password is visible. Its name does not change with its state: a pressed
  "Hide password" would announce the opposite of what it does. Its tooltip names the next action,
  "Show password" or "Hide password", for people who hover or tab to it. It is in the tab order, and
  pressing it with a pointer keeps focus and the on-screen keyboard in the input.
- The password is never written to the DOM outside the input's value: no `value` attribute, no data
  attribute and no announcement contains it. Spell checking, autocorrect and autocapitalise are off,
  so a revealed password is not sent to a spelling service.
- The Caps Lock warning appears only while the field has focus and is announced politely.
- The meter has the `meter` role with the strength as its value text. The checklist is part of the
  input's description, and changes are announced politely after typing pauses, only while the field
  has focus.
- Strength is shown by text as well as colour.
- Contrast is checked with axe in light, dark and RTL by `password-field.test.tsx`.
